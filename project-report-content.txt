4. ABSTRACT
============================================================

KSPK Foods is a full-stack web-based food ordering platform developed to simplify the process of browsing food items, placing orders, managing restaurants, and monitoring operations through an admin panel. The system provides separate roles for customers, restaurants, and administrators. Customers can search for food, view details, add items to cart, place orders using Cash on Delivery or Stripe card payment, manage their profile and address, and write reviews after successful purchases. Restaurant users can register, wait for admin approval, and then manage menu items and orders. Administrators can supervise the entire platform, approve restaurants, manage food listings, monitor orders, and create admin accounts.

The frontend of the project is built using React, Vite, Bootstrap, and Axios, while the backend is built using Node.js, Express.js, and MongoDB. The project demonstrates practical implementation of authentication, role-based access, payment integration, database operations, and modern web application development.

13. PROJECT MODULES
============================================================

Customer Module:
The customer module allows users to register, log in, search food items, filter by category, view food details, add products to cart, place orders, make payments, manage their address and profile, and view order history. Customers can also submit reviews only after a successful order.

Restaurant Module:
The restaurant module allows restaurant users to register on the platform and access the dashboard only after approval by the admin. Approved restaurants can add food items, manage menu data, and monitor customer orders.

Admin Module:
The admin module gives administrative control over the entire platform. Admin users can approve or reject restaurants, manage food items, monitor all orders, view dashboard insights, and create other admin accounts.

Payment Module:
The payment module supports two methods: Cash on Delivery and Stripe card payment. COD creates the order immediately, while card payment is processed using Stripe payment flow.

Review Module:
The review module stores ratings and reviews in the backend. It ensures that only customers who successfully ordered a food item are allowed to review it.

Contact Module:
The contact module saves customer messages in MongoDB and can also send emails if email credentials are configured.

============================================================
14. PROJECT ARCHITECTURE
============================================================

The project follows a client-server architecture.

1. Frontend:
The frontend is developed in React and provides all user interfaces such as home page, food exploration, cart, profile, order pages, and dashboards.

2. Backend:
The backend is built with Express.js and handles API requests, authentication, business logic, payment flow, database communication, and role-based access control.

3. Database:
MongoDB stores user data, food data, orders, reviews, contact messages, and restaurant details.

4. External Services:
Stripe is used for card payment processing, Cloudinary is used for media handling, and Nodemailer is used for email support where configured.

18. WORKING OF THE SYSTEM
============================================================

Signup Flow:
Customer signup first collects account details. Address information is completed in the next step. Restaurant signup collects restaurant-related details during registration.

Food Browsing Flow:
Customers can browse food items without location restriction, search products, filter by category, and open a detailed page for each food item.

Cart and Checkout Flow:
Customers add items to cart and proceed to place the order. The application calculates order details and provides payment choices.

Payment Flow:
If Cash on Delivery is selected, the order is created immediately and marked for cash collection. If card payment is selected, the order is created with Stripe payment handling and confirmed on the frontend.

Review Flow:
Reviews are stored in the backend on food records. Only customers with a successful order containing that food item can submit a review.

Admin Approval Flow:
Restaurant accounts are not allowed to use the restaurant dashboard until an admin approves them.
